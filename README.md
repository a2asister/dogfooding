# Performance Analyzer - Chrome 性能分析插件

一个功能强大的前端性能分析可视化工具，支持长任务检测、渲染耗时分析和内存泄漏排查，以图表形式直观展示性能数据。

## 功能特性

### 1. 实时性能概览
- **FPS 监控**：实时显示页面帧率，帮助识别卡顿问题
- **长任务统计**：统计并显示阻塞主线程的长任务数量
- **内存使用**：实时监控 JavaScript 堆内存使用情况
- **绘制次数**：记录页面重绘操作的次数

### 2. 长任务检测
- 自动检测并记录超过 50ms 的长任务
- 以柱状图形式展示各长任务的耗时分布
- 详细列表显示每个长任务的开始时间、耗时和类型
- 不同颜色标识任务严重程度（红色：>200ms，黄色：>100ms）

### 3. 渲染耗时分析
- 监控页面绘制（Paint）和布局偏移（Layout Shift）事件
- 折线图展示渲染耗时趋势
- 详细表格记录每次渲染操作的类型、时间和耗时
- 帮助识别不必要的重排和重绘操作

### 4. 内存分析
- 实时监控 JavaScript 堆内存使用情况
- 折线图展示内存使用趋势，帮助识别内存泄漏
- 显示已用内存、总内存和内存限制
- 持续监控可发现潜在的内存泄漏问题

## 安装说明

### 方法一：开发者模式安装（推荐）

1. 下载或克隆此项目到本地
2. 准备图标文件（将 SVG 转换为 PNG）
   - 由于 Chrome 扩展需要 PNG 格式的图标，你需要将 `icons/` 目录下的 SVG 文件转换为 PNG 格式
   - 可以使用在线工具如 [Convertio](https://convertio.co/svg-png/) 或 [CloudConvert](https://cloudconvert.com/svg-to-png)
   - 确保生成以下尺寸的 PNG 文件：
     - icon16.png (16x16 像素)
     - icon48.png (48x48 像素)
     - icon128.png (128x128 像素)
   - 将转换后的 PNG 文件放入 `icons/` 目录

3. 打开 Chrome 浏览器，访问 `chrome://extensions/`
4. 开启右上角的「开发者模式」
5. 点击「加载已解压的扩展程序」
6. 选择项目所在的文件夹
7. 安装完成后，浏览器工具栏会出现插件图标

### 方法二：打包安装

1. 完成上述步骤 1-2
2. 在 `chrome://extensions/` 页面点击「打包扩展程序」
3. 选择项目文件夹，生成 `.crx` 安装文件
4. 将 `.crx` 文件拖入 `chrome://extensions/` 页面进行安装

## 使用方法

1. 安装完成后，点击浏览器工具栏中的插件图标
2. 插件会自动开始监控当前标签页的性能数据
3. 通过顶部标签页切换不同的性能分析视图：
   - **概览**：查看 FPS、长任务数、内存使用和绘制次数的实时数据
   - **长任务**：查看长任务的分布图表和详细列表
   - **渲染耗时**：查看渲染操作的趋势图和详细记录
   - **内存分析**：查看内存使用趋势和详细信息

4. 操作按钮说明：
   - **刷新数据**：立即获取最新的性能数据
   - **清除数据**：清空所有已采集的性能数据

## 技术实现

### 核心技术栈
- **Chrome Extension Manifest V3**：最新的扩展程序标准
- **Performance API**：浏览器性能监控接口
- **PerformanceObserver**：性能事件观察者
- **Chart.js**：图表可视化库
- **原生 JavaScript**：无额外框架依赖

### 数据采集原理

1. **长任务检测**：
   - 使用 `PerformanceObserver` 监听 `longtask` 类型的性能条目
   - 记录超过 50ms 的任务，包括开始时间、耗时和类型

2. **渲染耗时分析**：
   - 使用 `PerformanceObserver` 监听 `paint` 和 `layout-shift` 类型的性能条目
   - 记录页面绘制和布局偏移事件的时间和耗时

3. **内存监控**：
   - 使用 `performance.memory` API 获取 JavaScript 堆内存信息
   - 每秒采集一次内存使用数据，包括已用内存、总内存和内存限制

4. **FPS 计算**：
   - 使用 `requestAnimationFrame` 计算帧率
   - 每秒统计一次平均 FPS 值

### 架构设计

- **content.js**：内容脚本，注入到页面中，负责采集性能数据
- **background.js**：服务工作者，负责管理标签页和数据通信
- **popup.html/js/css**：弹出页面，负责数据可视化和用户交互

## 性能指标说明

### FPS (帧率)
- **优秀**：60 FPS 及以上
- **良好**：30-59 FPS
- **较差**：低于 30 FPS

### 长任务
- **轻微**：50-100ms
- **中等**：100-200ms
- **严重**：超过 200ms

### 内存使用
- 关注内存使用趋势，持续增长可能表示内存泄漏
- 注意比较已用内存和总内存的比例

## 常见问题

### 1. 插件无法获取数据？
- 确保当前页面不是 `chrome://` 开头的内部页面
- 刷新页面后再次尝试
- 检查插件是否有足够的权限

### 2. FPS 显示为 0 或 --？
- 页面可能处于后台或未激活状态
- 页面可能没有动画或交互操作
- 刷新页面后再次尝试

### 3. 内存数据不显示？
- 某些浏览器可能不支持 `performance.memory` API
- 确保使用的是 Chrome 浏览器
- 尝试刷新页面

### 4. 图表显示异常？
- 确保网络连接正常，Chart.js 需要从 CDN 加载
- 尝试刷新弹出页面
- 检查是否有足够的性能数据

### 自定义修改

1. **修改采集频率**：
   - 在 `content.js` 中修改内存监控的间隔时间
   - 当前设置：`setInterval(..., 1000)` 即每秒采集一次

2. **调整长任务阈值**：
   - 在 `content.js` 中修改长任务的判断条件
   - 当前设置：`if (entry.duration > 50)` 即超过 50ms 视为长任务

3. **修改图表样式**：
   - 在 `popup.js` 中修改 Chart.js 的配置选项
   - 可以自定义颜色、字体、动画等

4. **添加新的性能指标**：
   - 在 `content.js` 中添加新的 `PerformanceObserver`
   - 在 `popup.js` 中添加对应的图表和数据展示
